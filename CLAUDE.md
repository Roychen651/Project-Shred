# PROJECT SHRED — Executive Dashboard
### v3.1 · Date-First State Engine — Living technical documentation · maintained sprint-by-sprint (Sprints 1–15)

**Artifact file:** `ProjectShred.jsx` (single-file React component, default export)
**Stack:** React (hooks: `useState`, `useEffect`, `useRef`, `createContext`, `useContext`) · Tailwind CSS (core utilities + inline styles for exact hex/glow values, plus a small injected `<style>` block for real focus/hover/active states) · `lucide-react` icons · `tone` (Web Audio blips for haptic/sound feedback) · custom hand-rolled SVG throughout (rings, timers, sparklines, dual trendlines, heatmap — no charting library anywhere).
**Language/Direction:** Hebrew, `dir="rtl"`, with a deliberate typeface pairing — Frank Ruhl Libre (display/headings), Heebo (body), JetBrains Mono (all numerals, tabular figures) — see the Design Quality Pass section below for why.
**In-app self-documentation:** this entire file's key sections (changelog, state architecture, formulas, component tree) are also viewable *inside the running app* via Settings → "ארכיטקטורה ותיעוד" (Sprint 12), rendered by a small custom `MarkdownLite` component — no external markdown library needed.

## Design System (as of the Design Quality Pass, post-Sprint 8)
The original stock palette and single-font setup read as generic AI-dashboard output, so the token layer was rebuilt from scratch. Everything still flows through `const T = useTheme()`, but the values behind it changed:

**1. Typography — a real pairing, not "Heebo everywhere"**
| Role | Face | Why |
|---|---|---|
| Display (`FONT_DISPLAY`) | `Frank Ruhl Libre` | A serif purpose-built for Hebrew+Latin, used across premium Israeli editorial design — gives headings real character instead of body-text-but-bigger. Applied to `h1`/section `h3` titles only. |
| Body (`FONT_BODY`) | `Heebo` | Neutral, highly legible, full Hebrew glyph support — everything that isn't a heading. |
| Numerals (`FONT_MONO`) | `JetBrains Mono` | Every number in the app (macros, BMR/TDEE, weights, sets). `font-variant-numeric: tabular-nums` is set globally so columns of digits align. |

**2. Color — derived jewel tones, not stock Tailwind hues**
The old `emerald-500 / cyan-500 / violet-500 / amber-500` set *was* the generic-AI tell (literally Tailwind's defaults, undesaturated and neon on a dark background). Replaced with `JEWEL`, a hand-derived, desaturated set with separate dark/light-surface variants:
| Family | Dark-surface | Light-surface | Used for |
|---|---|---|---|
| Jade | `#3F8D6E` | `#307E5F` | Protein, "Emerald" accent option |
| Bronze | `#CE8027` | `#B8701E` | Calories, "Gold" accent option |
| Steel | `#548BB6` | `#3A77A6` | Carbs |
| Plum | `#9064AF` | `#7D49A2` | Fat, "Violet" accent option |
| Petrol | `#3E8B98` | `#2E7C8A` | "Cyan" accent option, Power-day workouts |

`getMacroColors(mode)` and `getAccentHex(mode, accentKey)` pick the right variant automatically — accent and macro colors are genuinely mode-aware now (slightly softer in dark mode, slightly deeper/more saturated in light mode for contrast), rather than one flat hex reused everywhere regardless of surface.

**3. Neutrals — warm-tinted, never pure black/white**
Dark base moved from a cool blue-black (`#090A0F`) to a warm charcoal (`#0E0C0A`, card `#17130F`); light base is a warm alabaster (`#FBF9F6`) rather than cool slate. Both share the same warm temperature so dark/light feel like one system, not an inverted default.

**4. Elevation — restrained, not neon-glow-on-everything**
`glow()` intensities were cut roughly in half across the app (most buttons went from ~55-77 alpha glow to ~30-40). Cards moved from translucent "glassmorphism-by-default" to solid matte surfaces (`T.t.card` is now an opaque hex, not `rgba(...)`); `backdrop-blur` is reserved for modals/dropdowns only, where there's an actual translucent layer underneath to justify it.

**5. Real interactive states**
The injected `<style>` tag now defines actual CSS (not just inline JS styles) for `input`/`textarea` focus rings (accent-colored, `!important` to win over inline border colors), hover states, `button:active { scale(0.97) }` press feedback, a custom scrollbar, and `::selection` in the accent color — these didn't meaningfully exist before and are a large part of why the UI felt flat.

**6. Radius/spacing**
Inputs and buttons standardized on `rounded-xl` (12px); cards on `rounded-2xl` (16px); modals get a custom larger radius via inline style. `FieldInput` (Settings modal) was rebuilt with a tracked mono caption label, chip-style unit suffixes, and tabular numerals — previously it used flat labels and a silently-broken arbitrary Tailwind class (`min-w-[120px]`, which doesn't work without a JIT compiler) on the Metric Tracker's weight/waist inputs; both are fixed.

> Because Tailwind's JIT compiler is unavailable in the artifact sandbox, arbitrary-value classes (`bg-[#...]`, `min-w-[120px]`) silently do nothing — this was actually happening in a couple of spots and has been corrected. All exact hex values, glows, gradients, and now focus/hover states are applied via inline `style` or the injected `<style>` tag's plain CSS, never Tailwind's `dark:` variant or bracket syntax.

### Sprint 6 — Profile & Custom Goals Engine
**New constants/functions:** `ACTIVITY_LEVELS`, `GOALS`, `DEFAULT_PROFILES`, `computeProfileTargets()`.

- **Settings Modal** (`SettingsModal`) — gear icon in header opens an obsidian glass modal (`backdrop-blur-xl`, cyan glow border, scale/opacity transition). Fields: name, age, weight, height, waist, activity level (3-way), goal (4-way).
- **Mifflin-St Jeor engine**, live on every keystroke:
  - `BMR = 10×weight + 6.25×height − 5×age + 5`
  - `TDEE = BMR × activity multiplier` (sedentary ×1.2 / office+walks ×1.55 / very active ×1.75)
  - `Rest-day kcal = TDEE × (1 + goal%)` — aggressive cut −25%, moderate cut −15%, maintain 0%, bulk +12%
  - `Protein = 2.0g/kg`, `Fat = 0.7g/kg`, `Carbs = remainder` (`(kcal − protein_kcal − fat_kcal) / 4`)
  - `Training-day kcal = Rest-day + 300`, delivered entirely as `+75g` carbs (matches the existing Sprint-1 carb-refeed pattern exactly: 75g × 4kcal = 300kcal).
  - This **replaces** the old hardcoded `TARGETS` object — the Macro Engine, target strip, and timeline now all read from `computeProfileTargets(activeProfile)`.
- **Multi-Profile Switcher** (`ProfileSwitcher`) — header badge (name + weight) opens a dropdown: default `הפרופיל שלי` (84kg/171cm) and `פרופיל אורח / חבר`, plus unlimited custom profiles (name + template defaults, deletable). Switching profiles instantly recalculates BMR/TDEE/macros and reseeds the Weekly Metric Tracker's first data point.
- **Persistence — important platform note:** the spec asked for `localStorage`. **`localStorage`/`sessionStorage` are explicitly unsupported inside Claude.ai artifacts** and will silently fail. Persistence is implemented instead with the artifact's native `window.storage` key-value API (`STORAGE_KEY = 'project-shred-state'`, personal/non-shared scope), which is the supported equivalent — profiles + active profile ID auto-save ~350ms after any change, with a small "שומר… / נשמר" indicator in the header.
- **Export/Import JSON** — Export builds a `Blob` + object URL and triggers a download of `project-shred-profiles.json`. Import reads a chosen file via `FileReader`, `JSON.parse`s it, and restores `profiles`/`activeProfileId` (invalid files are ignored safely).

### Sprint 7 — Theme, Accent & Density Engine
**New architecture:** a `ThemeContext` (`createContext`/`useContext`) now wraps the whole app. Every component reads `const T = useTheme()` instead of importing a hardcoded color object — this is the single biggest structural change since Sprint 1, and it's what makes live theme/accent/density switching possible without prop-drilling through 15+ components.

- **`THEME_PRESETS.dark` / `.light`** — full token sets (`bg`, `card`, `border`, `textPrimary/Secondary/Dim`, `inputBg`, `popover`, `modalBg`, `overlayBg`, `shadowCard`, etc.). Dark = obsidian (`#090A0F` base, translucent glass cards). Light = "Executive Alabaster" (`#F8FAFC` base, solid white cards, slate borders `#E2E8F0`, soft slate drop-shadows instead of black ones). **Every** `text-white` Tailwind className from Sprints 1-6 was removed and replaced with `style={{ color: T.t.textPrimary }}` — this was required because a hardcoded white className would be invisible on light-mode's white cards.
- **`ACCENT_PRESETS`** — 🟢 Emerald (default) / 🔷 Cyan / 🟣 Violet / 🟡 Gold. The chosen accent hex drives every *interactive/brand* surface: tab actives (Cibus matrix), confirm/add/new-profile buttons, timeline checkmarks, workout set-done circles, rest-timer ring, profile badge avatar + active row, settings modal border-glow, all Eyebrow labels & arena icons. **Design decision:** the four macro-engine colors (kcal=amber, protein=emerald, carbs=blue, fat=violet in `MACRO_COLORS`) and the goal-picker colors (`GOALS[key].color`) stay **fixed regardless of accent** — they encode data meaning, not brand identity, so recoloring them on accent change would hurt readability rather than help it. This is documented here so it isn't mistaken for an incomplete binding.
- **`DENSITY_PRESETS.comfortable` / `.compact`** — a single `spacing` object (`section`, `card`, `cardSm`, `gap`, `ring`, `timelineGap`, `showDetail`) is threaded through every Arena wrapper, `GlassCard`, `Ring`, and grid gap. Compact mode also sets `showDetail: false`, which hides the descriptive sub-text in Timeline slots and Hack cards (the "dense macro chips" behavior) to cut vertical scroll height.
- **Haptic & Sound feedback (`feedback` toggle, Settings modal)** — `playFeedback()` fires on every checkbox/set/confirm/add tap: `navigator.vibrate(12)` where supported, plus a real audible blip via a lazily-created `Tone.Synth` (`Tone.start()` + `triggerAttackRelease('C6','32n')`, wrapped in try/catch so it never throws in environments without audio). A companion `usePulse()` hook drives a `transform: scale(1.2–1.25)` micro-animation on the tapped element for ~350ms — the visual "ripple."
- **Persistence** — same platform caveat as Sprint 6: the spec's `localStorage` isn't available inside Claude.ai artifacts, so `mode`, `accentKey`, `density`, and `feedback` are folded into the existing `window.storage` payload under `STORAGE_KEY` (`{ profiles, activeProfileId, theme: { mode, accentKey, density, feedback } }`) and round-trip through the same Export/Import JSON flow from Sprint 6.
- **Header** now carries a quick 🌙/☀️ toggle (instant dark/light swap) in addition to the full picker inside Settings, per spec.

### Sprint 9 — AI Coach Hub & Natural Language Parser Engine
**New constants/functions:** `FOOD_DB`, `parseFoodText()`, `MENTAL_TIPS`, `generateAiReport()`.
**New components:** `AiCoachWidget`, `ScoreBadge`, `ParsedItemRow`, `SmartSwapAlerts`.

- **Everything here is a deterministic, explainable, 100%-client-side heuristic engine — not a real LLM call.** This is a deliberate choice, not a shortcut: the spec explicitly asked for a "Zero-Key" engine that works offline out of the box, and wiring a browser-side `fetch` to a real LLM provider with a user-pasted key would mean either exposing that key to whatever third-party endpoint the user configured, or silently failing on that provider's CORS policy (most LLM APIs block direct browser calls). Neither is something to ship quietly, so the working feature is the rule-based engine described below, and the API key field is honestly labeled as inert/for-later rather than pretending to be live.
- **`AiCoachWidget`** sits in a new **ARENA 00**, above the Macro Engine, so it's the first thing after the target strip.
  - **"ניתוח יום אולימפי"** button runs `generateAiReport({ consumed, targets, dayMode })`: a weighted score (`proteinScore × 0.6 + kcalScore × 0.4`, where `kcalScore` penalizes distance from target in either direction), a tactical sentence chosen from `if/else` rules on the protein gap and calorie gap (reusing the same Kitchen Hacks/Cibus vocabulary the rest of the app uses, e.g. "טוסט חלבון + פסטרמה"), and a mental/recovery one-liner pulled from a small `MENTAL_TIPS` pool keyed by `dayMode`. A short simulated "מנתח נתונים…" delay (600ms, `Loader2` spin) gives the button honest, deliberate feedback — the computation itself is instant, but presenting it as considered rather than a snap client-side calc is the appropriate register for a "coach" persona.
  - **`SmartSwapAlerts`** computes two independent, dismissible banners live on every render: a protein-gap suggestion (`new Date().getHours() >= 17 && targets.protein − consumed.protein > 30`) and a calories-near-limit suggestion (`consumed.kcal >= targets.kcal × 0.9`). Both use the exact copy from the spec.
  - **Quick-log NLP parser** (`parseFoodText`): scans free Hebrew text against `FOOD_DB` (~19 common foods/snacks) by keyword substring match, then inspects a small window immediately **before** each match for a quantity (`"200 גרם"` style) and a window immediately **after** for trailing Hebrew size adjectives (`קטנה`/`גדולה`/`חצי` — adjectives follow the noun in Hebrew, e.g. "במבה **קטנה**", so this has to check *after* the keyword, not before, which is the detail that makes it work for both of the spec's example sentences). Foods are either `per100g` (chicken, rice, salmon…, scaled by grams) or `perUnit` (egg, banana, Bamba, protein pudding…, scaled by count). Parsed results render as an editable preview (remove-before-confirm), then **"אשר והוסף ליומן"** pushes them into `quickLogItems`, which is summed directly into the same `consumed` object the Macro Engine rings already read from — so a quick-logged item moves the rings exactly like checking a timeline slot does.
- **Optional API connection field** (Settings modal, new "חיבור AI" section): provider selector (none/Groq/OpenAI/HuggingFace) + password-style key input. Explicitly labeled as inert in this build. **Security note:** the raw key is deliberately stripped out of both the `window.storage` payload's export path and is never written into the downloaded JSON backup (`handleExport` always writes `key: ''`), and import never restores a key from a file — only the provider choice round-trips. The key itself only ever lives in React state + the personal (non-shared) `window.storage` entry for this artifact.
- **Persistence** — `quickLogItems`, `aiReport`, and `apiConfig.provider` (never the key) are folded into the same `STORAGE_KEY` payload and auto-saved like everything else in Sprints 6-8.

### Sprint 10 — Executive Analytics, Heatmap & Report Export Engine
**New constants/functions:** `TARGET_WAIST_CM`, `HEATMAP_WEEKS`, `dateKey()`, `addDays()`, `formatShortDate()`, `scoreDayLog()`, `heatColor()`, `seedDailyLogs()`, `seedMetricEntries()`, `buildHeatmapColumns()`, `buildWeeklyReport()`.
**New components:** `ComplianceHeatmap`, `HeatmapDetail`, `DayEditor`, `DualTrendChart`, `WeeklyReportModal`.

- **Data model change:** the app previously had no real historical log — "today" was the only state that existed (checked timeline slots, lunch/dinner choice, quick-log items). Sprint 10 introduces `dailyLogs` (an object keyed by `YYYY-MM-DD`, each value `{ kcal, protein, carbs, fat, workoutDone, workoutDay }`) and lifts the weight/waist log (previously local `MetricTracker` state, week-indexed) up to the main component as date-indexed `metricEntries`, both persisted like everything else.
- **First-visit seeding:** `seedDailyLogs()` and `seedMetricEntries()` generate ~6 weeks / 8 biweekly points of plausible synthetic history (a rough 4-day upper/lower cadence with randomized ±noise around the profile's real targets, trending toward the profile's actual current weight/waist) so the heatmap and trendline are never empty on a first run. **Today's cell is never synthetic** — a `useEffect` keyed on `consumed`/`workoutActivity` continuously upserts `dailyLogs[todayKey]` from the *live* Macro Engine + Workout Tracker state, so the heatmap's rightmost, newest cell always reflects what's actually on screen right now.
- **`ComplianceHeatmap`** — a GitHub-style grid, `HEATMAP_WEEKS` (6) columns × 7 rows, rendered inside a `dir="ltr"` wrapper so weeks flow chronologically left-to-right (a deliberate exception to the app's RTL default, the same way calendar/temporal grids conventionally do). Each day's score comes from `scoreDayLog()` (50% protein accuracy + 50% calorie accuracy against whichever target — training or rest — that day's `workoutDone` flag implies) and buckets into 3 fixed colors via `heatColor()`: jade (≥90, "on point"), bronze (75-89, "slight deviation"), plum (<75, "needs attention"), or a neutral gray chip for genuinely unlogged days. **Simplification:** columns are built by chunking the last 42 days sequentially into groups of 7, not calendar-aligned to actual Sunday-start weeks — visually still reads as a heatmap, but isn't pixel-identical to GitHub's Sunday-aligned grid.
  - Hovering (desktop) or tapping (any device) a cell updates a detail panel below the grid (`HeatmapDetail`) showing that day's date, score, calories/protein vs. that day's target, and workout status — this is the "hover/click tooltip" requirement, implemented as a persistent detail panel rather than a cursor-following tooltip so it works identically on touch and mouse.
  - **`DayEditor`** — clicking "ערוך יום זה" on the selected day's detail panel opens an inline form (kcal, protein, workout-done checkbox) that writes straight into `dailyLogs[key]`, satisfying the retroactive backfill/edit requirement — this works on both seeded historical days and today.
  - **"איפוס נתוני שבוע אחרון"** deletes the 7 keys in the most-recently-displayed column, immediately reverting those cells to unlogged/gray.
- **`DualTrendChart`** — a single custom SVG (no charting library) plotting weight and waist on two independent normalized y-scales sharing one x-axis (`metricEntries`), plus a dashed horizontal line at `TARGET_WAIST_CM` (90cm, per spec) computed on the waist scale — this is the "fat-loss trajectory" target-line overlay. `MetricTracker`'s compact per-metric sparklines and this combined chart now read from the exact same `metricEntries` array, so a manual entry added in Arena 05 immediately extends the Arena 06 trendline too.
- **`WeeklyReportModal`** (`buildWeeklyReport`) — pulls the last 7 calendar days out of `dailyLogs` to compute average compliance score, average daily protein, and completed workout-day count, and diffs the most recent two `metricEntries` for the weight/waist deltas. Renders as a 4-stat card grid, plus **"העתק דוח ל-WhatsApp"**, which formats the same numbers into an emoji-rich Hebrew message and writes it to the clipboard via `navigator.clipboard.writeText()` (with a 2-second "הועתק!" confirmation state).

### Sprint 11 — Custom Cibus, Kitchen Hacks & Smart Swaps Recipe Engine
**New constants/functions:** `HACK_EMOJIS`, `newId()`, `emptyFoodItem()`, `emptyRestaurant()`, `emptyHack()`, `buildFoodLibrary()`, `findBestMatches()`.
**New components:** `GenericDishList`, `GenericPlateBuilder`, `RestaurantBuilderModal`, `ItemRowEditor`, `HackBuilderModal`.

- **Custom Cibus restaurants** — "ערוך/הוסף מסעדה" in the Cibus Matrix header opens `RestaurantBuilderModal`. Each custom restaurant is one of two shapes, matching the two patterns the built-ins already established:
  - `type: 'simple'` — a flat list of discrete dishes (the Goomba/Kansai pattern), each edited as a `{ name, kcal, protein, carbs, fat }` row via `ItemRowEditor`, rendered at selection time through the new generic `GenericDishList`.
  - `type: 'plate3'` — a genuine 3-part-formula restaurant (the Shumshum pattern): three independently-editable option lists (veg/protein/carb), rendered through `GenericPlateBuilder`, which is the exact same combinatorial logic `ShumshumBuilder` uses, just fed user-defined options instead of the hardcoded `SHUMSHUM` constant.
  - **Scope decision:** the four original built-in restaurants (Shumshum, Chicken Station, Goomba, Kansai) stay fixed/hardcoded, as explicit reference examples the sprint history has already validated — the spec's "customize the 3-part formula... for any custom restaurant" is satisfied by giving *new* restaurants the same editable-plate-formula power, rather than making the built-ins' option lists mutable. This was a deliberate scope call to avoid touching four already-working, previously-shipped components; it's noted here rather than silently narrowing the request.
  - Custom restaurants show up as extra tabs in the Cibus Matrix automatically. The active tab shows a "מותאם אישית" badge plus inline "ערוך"/"מחק" controls when it's a custom one.
- **Custom Kitchen Hacks** — "הוסף מתכון אישי" opens `HackBuilderModal`: name, a 12-emoji icon picker (`HACK_EMOJIS`), and kcal/protein/carbs/fat fields. Saved recipes are concatenated (`[...HACKS, ...customHacks]`) and rendered through the existing `HackCard` unchanged except for two additions: a "מותאם אישית" badge and, only for custom items, an edit pencil that reopens the same modal pre-filled (`HackCard` now accepts an optional `onEdit`).
- **Smart Swap engine ("מה לאכול עכשיו?")** — added inside the existing `AiCoachWidget` (Sprint 9) rather than as a separate arena, since it's the same "recommendation" surface conceptually. `buildFoodLibrary()` doesn't just list the built-in restaurants' named dishes — it actually **enumerates every combination** the Shumshum/Chicken-Station/Kansai builders can produce (veg × protein × carb, etc.), plus Goomba's two dishes, plus every Kitchen Hack (built-in and custom), plus every custom restaurant's dishes or plate-combinations. `findBestMatches()` scores each candidate by weighted distance from the day's *remaining* calorie/protein gap (`targets − consumed`) and returns the top 3. Each result has a one-click **"אשר ואכול"** that logs it straight into `quickLogItems` (the same Sprint 9 pipeline), so it immediately moves the Macro Engine rings.
- **Persistence** — `customRestaurants` and `customHacks` are folded into the same `STORAGE_KEY` payload and round-trip through export/import like every other data type since Sprint 6.

### Sprint 12 — PROJECT SHRED 2.0: System Docs, Diagnostics & Sign-Off
**New constants:** `APP_VERSION`, `DOCS_CHANGELOG`, `DOCS_ARCHITECTURE`, `DOCS_FORMULAS`, `DOCS_COMPONENT_TREE`.
**New functions:** `runIntegrityChecks()`, `buildFullBackup()`.
**New components:** `MarkdownLite`, `renderInline`, `DocsViewerModal`, `IntegrityRow`, `DiagnosticsModal`, `CertificateModal`.

- **In-app documentation viewer** — Settings → "ארכיטקטורה ותיעוד" opens `DocsViewerModal`, a 4-tab viewer (changelog / state architecture / formulas / component tree) rendering plain-text content through a **hand-rolled `MarkdownLite` renderer** (handles `## headings`, `- bullets`, `` `inline code` ``, and `**bold**` — no markdown library was available in this environment, so this is a small, purpose-built subset parser rather than a full CommonMark implementation). The four content blocks are condensed, hand-maintained summaries of this very file's Sprint Log / Design System / formulas sections — when this `CLAUDE.md` changes materially, `DOCS_CHANGELOG`/`DOCS_ARCHITECTURE`/`DOCS_FORMULAS`/`DOCS_COMPONENT_TREE` should be updated to match, since they're independent copies embedded in the JS bundle, not a live parse of this file.
- **`DiagnosticsModal`** (Settings → "דיאגנוסטיקת מערכת"):
  - **Storage usage** — `buildFullBackup()` assembles the exact same object shape used for JSON export, and `JSON.stringify(...).length / 1024` gives a real KB figure for what's actually sitting in `window.storage` — not a placeholder number.

### Sprint 15 — Date-First State Engine & Unified Item Schema (Core Stability Refactor)
**New constants:** `SLOT_DEFS` (unifies what Sprint 13's `PORTION_SLOTS` used to be — kept as an alias for compatibility).
**New functions:** `makeLoggedItem()`, `scaleLoggedItem()`, `sumItems()`, `shiftDateKey()`, `formatHebrewDate()`, `getCurrentSlotId()` (rewritten), `markSlotCompleted()`.
**New components:** `DateNavigator`, `ItemLogRow`, `ItemEditSheetBody`, `Timeline` (rewritten), `SmartContextCard` (rewritten).

- **This sprint found and fixed a real, pre-existing bug while rebuilding the logging core:** the Shumshum tab in the Cibus Matrix had lost its render branch (`{tab === 'shumshum' && <ShumshumBuilder .../>}`) somewhere in an earlier sprint's edit — selecting that tab silently showed nothing. It's restored as part of this rewrite. This is exactly the class of problem a unified, single-source-of-truth data model is meant to prevent going forward.
- **The data model change, in full:** every previous per-slot, per-feature state (`checked`, `lunch`, `dinner`, `breakfastMeal`, `midmorningMeal`, `preworkoutMeal`, `quickLogItems`) is gone, replaced by exactly two pieces of state: `selectedDateKey` (a `YYYY-MM-DD` string) and `itemsByDate` (an object keyed by date, each value an array of logged items). **Every** food-logging surface in the app — Cibus, Kitchen Hacks, the Plate Composer, the AI Coach's quick-log parser and Smart Swap, and the FAB's quick-log sheet — now calls the exact same function, `logItems(specs, slotId)`, which normalizes whatever it's given through `makeLoggedItem()`.
- **The unified item schema**, matching the spec's requested shape: `{ id, dateKey, slotId, name, baseCalories, baseProtein, baseCarbs, baseFats, grams, isCompleted, source }`. The `base*` fields are the macros as originally logged (at `grams = 100`, meaning "1× the recorded portion"); `scaleLoggedItem()` derives the *displayed* macros as `base × (grams / 100)`. This is what makes portion editing work uniformly for every kind of logged food — a raw ingredient, a whole Cibus plate, or a quick-log-parsed snack — even though none of them share an actual "per-gram" nutrition rate in the way a single raw ingredient does. `grams` is therefore a **portion index**, not a literal weight, for anything that isn't a raw ingredient — documented here so it isn't mistaken for a literal gram count.
- **100% reversible toggling** — `toggleItemCompleted(itemId)` flips one boolean on one item in the current date's array; there is no longer any shared "slot state" to get out of sync, so a checkbox can never get stuck. `deleteItem(itemId)` removes an item outright (subtracting its macros automatically, since totals are always a live sum, never a running counter). `updateItem(itemId, patch)` handles both quantity and slot reassignment through the same path, surfaced via `ItemEditSheetBody` (tapping any logged item's pencil icon opens a portion slider + 5-slot re-assignment grid).
- **`DateNavigator`** — `< יום קודם | היום, 24 ביולי | יום הבא >` plus a tappable date label that expands a 14-day picker strip (today ±10/+3 days), and a floating "חזרה להיום" pill that appears whenever `selectedDateKey` isn't today. Placed at the top of both the Today and Nutrition tabs. Changing the date swaps `dayItems` (and therefore every ring, the Timeline, and the Smart Context Card) to that date's logged items instantly — there is no separate "load" step.
- **`Timeline` rewrite** — now renders all 5 `SLOT_DEFS` as groups, each listing however many items are actually logged in it (zero, one, or several — multiple items per slot is now fully supported, which is more correct than the old one-meal-per-slot model). Each item is an `ItemLogRow` with its own toggle, edit, and delete controls. Empty slots show a quiet placeholder instead of a fake default meal.
- **Universal slot selection** — `CibusMatrix`, `HackCard` (via a small inline emoji picker that appears in place of the "add" button), the AI Coach's quick-log and Smart Swap sections, and the FAB's `QuickLogSheetBody` all now expose the same 5-slot picker (🌅🍏🍲🍌🍳) before anything is logged, rather than being hardcoded to a single slot each.
- **Analytics integration** — the heatmap's daily totals now come from real summed items (`sumItems`) for any date that has them, and fall back to the Sprint 10 synthetic seed only for dates the person has never actually logged anything on. The old "sync today's consumed into dailyLogs" effect was replaced with one that reconciles *every* date in `itemsByDate` on each change.
- **Persistence** — `itemsByDate` replaces the old fragmented per-slot fields in the `window.storage` payload, `buildFullBackup()`, export/import, and `factoryReset()`.

### Sprint 15.2 — Critical Date-Navigation Bugfix & Macro Clarity Redesign
Triggered by a direct bug report: navigating to "yesterday" was landing two days back instead of one (e.g. today 26/7 → "yesterday" showed 24/7 instead of 25/7), plus a repeated complaint that it still wasn't clear how many calories had been consumed vs. how many remained.

- **Root cause, found and fixed:** `dateKey()` formatted dates via `d.toISOString().slice(0, 10)` — but `toISOString()` converts to **UTC**, while every other date function in the app (`shiftDateKey`, `addDays`, "what time is it now") works in **local time**. In any timezone ahead of UTC (Israel is UTC+2/+3), a local-midnight `Date` serializes through `toISOString()` as the *previous* day. Because `shiftDateKey` builds a local-midnight date, shifts it, and then re-serializes through `dateKey()`, the bug's own −1-day error stacked on top of the intended shift — so "yesterday" landed 2 days back, "tomorrow" effectively didn't move, and so on. **Fix:** `dateKey()` now builds its string from `getFullYear()`/`getMonth()`/`getDate()` (local components) instead of `toISOString()`, matching every other date function's timezone assumption. Verified directly: today `2026-07-26` → yesterday `2026-07-25` → tomorrow `2026-07-27`.
- **Macro clarity redesign (Today tab):** the hero ring's center now leads with **"נצרכו היום"** and the actual consumed-calories number as the primary, biggest figure (not "remaining" as before, which was the source of the "unclear how much I've eaten" feedback), with "מתוך {target} קל׳" directly beneath it, and a colored pill below that — green "{N} נותרו" when under target, amber "+{N} מעל היעד" when over — so both consumed *and* remaining are always both visible and unambiguous, never one-or-the-other.
- **New `MacroBreakdownCard`/`MacroBar`** — replaces the old two-line carbs/fat footnote with a proper 4-row breakdown (calories, protein, carbs, fat), each a labeled horizontal progress bar with consumed/target figures — matching the pattern established nutrition apps (MacroFactor, Cronometer) use for "all four macros, always visible, always precise," rather than requiring the person to mentally reconstruct carb/fat progress from small inline text.

### Sprint 15.7 — Critical Bugfix: FAB Covering Sheet/Modal Buttons
Triggered by a screenshot showing the floating "+" action button sitting directly on top of the Plate Composer's "הוסף לצלחת" button, obscuring its text.

- **Root cause:** `ActionFab` was an always-rendered, fixed-position element (`z-40`, bottom-center) with no awareness of whether a `SheetModal` or full-screen modal was currently open. - **Follow-up fix (same sprint):** even with the above, the `FabMenu` popup itself (the 3-option launcher shown when tapping the FAB) still overlapped the "+" button, because its position used a Tailwind spacing class (`bottom-24` = 96px) that didn't actually clear the FAB's own height — the FAB sits at `bottom: 84px` and is `58px` tall, so its top edge is at `142px`, well above where the menu's bottom edge (96px) sat. The menu now uses a precisely computed inline `bottom: 158px` (FAB top edge + 16px gap) instead of a Tailwind spacing token, closing the gap between "looks right in the token scale" and "actually clears the other element's real pixel height."

### Sprint 15.8 — Critical Bugfix: Sheet Content Cut Off / Confusing Nested Scroll
Triggered by screenshots showing the Plate Composer sheet cutting content off at the bottom and requiring an awkward, "unprofessional-feeling" scroll.

- **Root cause #1 — double-carding:** `CibusMatrix` and `PlateComposerWidget` each wrapped their own content in a `<GlassCard>` (border + shadow + `p-5` padding) — a sensible default from when they were first built as standalone, inline sections. Since Sprint 14, both are **only ever rendered inside a `SheetModal`**, which already provides its own rounded card surface and padding (`px-5 pb-8`). The result was a card nested inside a card, each with its own padding, silently eating into the sheet's already height-constrained real estate — exactly the kind of shrinkage that makes a form feel cramped and cut off. Both components now render a plain `<div>` with no extra chrome; the sheet supplies the "card" look.
- **Root cause #2 — nested scrolling:** the ingredient list (Plate Composer) and dish list (Eating Out) each had their own `max-h-56`/`max-h-64` + `overflow-y-auto`, creating a small scrollable box *inside* the sheet's own scrollable body. Two independent scroll regions stacked on top of each other is a recognized "feels broken" pattern (unclear which area responds to a swipe, visible mid-page scrollbar). Both lists now flow as part of the sheet's single scroll container — one continuous scroll, like the rest of the app.
- **`SheetModal` itself improved:** height increased from a `maxHeight: 85vh` (with `overflow-hidden` fighting an inline `overflowY: auto` — an easy-to-miss CSS conflict) to a clean `height: 92vh` with a genuinely separate scroll region; the drag-handle + title + close button are now a `flex-shrink-0` sticky header that stays visible while the body scrolls, instead of scrolling away with the content.

### Sprint 15.9 — Critical Bugfix: the 15.8 "Fix" Introduced a Worse Regression
The 15.8 change (sticky header + single scroll region) was implemented via a flex-column layout — but in that same edit, `overflow: hidden` was dropped from the outer panel, and the new scrollable content `<div>` was missing `min-height: 0`. Both omissions matter more than they look:
- **Without `overflow: hidden`** on the outer rounded panel, anything that grows past the panel's `92vh` box is not clipped — it simply renders outside the panel's visual bounds, so the rounded "sheet" framing is only cosmetic until something overflows, at which point content appears to spill across the whole screen with no visible card edges at all.
- **Without `min-height: 0`** on a `flex: 1` child inside a `flex-column` parent, browsers apply a default `min-height: auto`, which means the child refuses to shrink below its *content's natural height* — so instead of being capped at "whatever space is left in the 92vh panel" and scrolling internally, the content area just grows to fit all ~171 ingredient rows, and (per the point above) that overgrowth wasn't being clipped either. Together, these two omissions reproduced the exact bug shown in the follow-up screenshots: the header appeared to float disconnected from the content, and the ingredient list rendered as an unbounded, unframed column filling the entire screen.
- **Fix:** `overflow: hidden` restored on the outer panel; `minHeight: 0` added to the scrollable content `<div>`. This is the standard, correct pattern for a fixed-height flex container with a non-scrolling header and a scrolling body — worth stating plainly here so a future edit doesn't reintroduce the same regression by "cleaning up" one of these two properties without understanding why both are load-bearing.

### Sprint 15.12 — The Real Root Cause, and a 3-Region Sticky Layout
Further screenshots showed the sheet appearing to "sink" progressively lower with more of the background page visible above it, undimmed. The actual cause, found this time: Sprint 15.10's own "fix" added `@media (min-width: 768px) { .shred-sheet-panel { max-height: 620px; } }` — intended as a desktop safety cap, but on any reasonably tall desktop window this **capped the sheet at a fixed 620px regardless of how tall the viewport actually was**, leaving a large empty gap between the top of the screen and the (now short) sheet — which, combined with a too-subtle light-mode backdrop dim (`rgba(36,31,26,0.32)`, barely darkening a light background), made the gap look like normal, undimmed page content rather than a modal overlay. **Fixed:** the desktop cap was replaced with a much more generous `82vh` (only applied when both width ≥768px *and* height ≥700px, so it never fights a genuinely short viewport), the base height raised to `86vh`/`88dvh`, and the light-mode overlay darkened to `0.52` alpha so it reads unmistakably as a dimmed backdrop.
- **The creative part, per explicit request — a real 3-region sticky layout, not just "make it taller":** `SheetModal` gained an optional `bare` prop. When set, the sheet stops forcing its own single auto-scroll region and instead hands a plain `flex-1 / min-height: 0 / overflow: hidden` container to its content, letting the child fully own its internal layout. `PlateComposerWidget` (used with `bare`) now explicitly splits into three `flex` regions: a `flex-shrink-0` **top** (icon/title, the 4 remaining-budget stat tiles, search, category tabs — always visible), a `flex-1 overflow-y-auto` **middle** (the ingredient list — and *only* the ingredient list — scrolls here), and a `flex-shrink-0` **bottom** (the selected ingredient's raw/cooked toggle, portion input, live macro tiles, "הוסף לצלחת," and — once items exist — the composed-plate summary and "אשר ושבץ" button; capped at `48vh` with its own small internal scroll only if the plate itself grows unusually long). This delivers exactly what was asked: calories/categories visible up top, quantity/add-to-plate visible at the bottom, with only the (potentially long) product list needing to scroll in between.

### Sprint 15.13 — Critical Bugfix: the 3-Region Layout Could Collapse the Ingredient List to Zero Height
Screenshots showed the ingredient list disappearing entirely — search reported "2 results" but showed none, category selection appeared to do nothing, and the previously-selected ingredient stayed stuck in the bottom panel with no way to pick a different one.

- **Root cause:** in the 15.12 three-region layout, both the top and bottom regions were `flex-shrink-0` (never allowed to shrink) while the middle (ingredient list) was `flex: 1` with `min-height: 0` (allowed to shrink all the way to nothing). The bottom region's cap (`max-height: 48vh`) was generous enough that, once a plate item existed, the bottom region's real content (selected-item detail panel *plus* the composed-plate summary *plus* the slot picker *plus* the assign button) could combine with the top region to exceed the sheet's total height — and since the middle was the only flexible region, flexbox satisfied that by shrinking it to its permitted minimum: **zero**. The list wasn't glitched or empty — it was rendering at 0px tall, which looks identical to "not there."
- **Fix, structural not cosmetic:** the composed-plate summary + slot picker + "אשר ושבץ" button moved *out* of the bottom sticky footer and *into* the scrollable middle region (rendered above the ingredient list, so it reads as a pinned cart summary at the top of the scroll). This means the bottom footer now only ever contains the single currently-selected ingredient's quick-add panel — a short, height-bounded block that can never grow large enough to squeeze anything out. The middle region also gained an explicit `min-height: 140px` safety net, so even in some future edit that re-introduces a tall footer, the ingredient list is guaranteed a visible minimum rather than being able to collapse to zero again.
- This single fix also resolved two complaints that looked separate but shared the same root cause: "can't select a different ingredient after picking one" and "search shows a result count but no selectable rows" — both were symptoms of the list being present in the DOM but rendered at zero height, not missing logic.

### Sprint 15.15 — Critical Bugfix: vh/dvh Don't Reliably Match the Real Visible Screen Here
Despite raising the sheet's CSS height repeatedly (Sprints 15.10, 15.12), a screenshot showed it still cut off at the bottom, and the search-result rows still weren't visible — both symptoms of the sheet's *actual usable space* being smaller than any vh/dvh percentage suggested.

- **Diagnosis:** CSS `vh`/`dvh` units are supposed to track the real visible viewport, but in some embedded/iframe hosting contexts they resolve against a taller reference than what's actually on screen — no amount of retuning the *percentage* fixes this, because the *100% itself* was the wrong number. This explains why every previous height adjustment "worked" in principle but kept coming up short in practice: the underlying unit was never trustworthy in this environment to begin with.
- **Fix — stop trusting the CSS unit, measure the real thing in JS:** a new `useViewportHeight()` hook reads `window.innerHeight` directly (with `resize`/`orientationchange` listeners to stay current), and `SheetModal` now sets its panel to `Math.round(vh * 0.85)` **pixels** — an actual measured number, not a CSS percentage of an unreliable reference. `window.innerHeight` reflects the real, current visible height of whatever browsing context the script is executing in, which is the standard, battle-tested workaround for exactly this class of vh-unreliability bug (the same technique many mobile-web modal libraries use to work around iOS Safari's own vh quirks). The now-unused `.shred-sheet-panel` CSS rules were removed.
- With the true available height finally accurate, the ingredient-list visibility problem (Sprint 15.13's fix) also gets meaningfully more room to work with, since the previous "cut off" bug meant the whole 3-region layout was working within a shorter-than-intended space to begin with.

### Sprint 15.22 — Code-Review Finding: `flex-shrink: 0` Was the Actual Culprit
With the second product's quick-add panel (region 4) still occasionally cut off, a closer read of the flex math turned up the specific line responsible: region 4 was set to `flex-shrink-0` (Tailwind's "never shrink this item"). When regions 1+3 (header, finalize bar — both also `flex-shrink-0`) plus region 2's forced minimum already consumed most of the panel's fixed height, region 4's `flex-shrink-0` meant it *still* claimed its full natural height regardless of what was actually left — pushing the total past the panel's boundary. Because the panel itself clips overflow (`overflow: hidden`, needed so nothing spills outside the rounded sheet), the part of region 4 that didn't fit was clipped away entirely, before its own internal `overflow-y: auto` ever got a chance to help — a scrollbar that never appears can't be scrolled.
- **Fix:** region 4 changed from `flex-shrink-0` to `flex: '0 1 auto'` with `min-height: 110` — it can now genuinely shrink when space is tight, which makes its `overflow-y: auto` actually activate and produce a real, usable internal scrollbar instead of being silently clipped by the parent panel. Region 2's forced minimum was also reduced (140px → 90px) to leave region 4 more room to negotiate for in the common case. This is the one-line class of bug that made every previous "fix" partially work and then fail again in a slightly different spot: giving several stacked flex children `flex-shrink: 0` without checking whether their combined natural heights could ever exceed the container guarantees exactly this failure mode, regardless of how each individual region is otherwise structured.

### Sprint 15.10 — Viewport-Height Overflow & Cross-Device Responsiveness
Triggered by a desktop screenshot showing the sheet panel's bottom edge cut off by the OS taskbar, plus a request that the whole app genuinely adapt across phone/tablet/desktop widths.

- **The `vh` unit problem:** `height: 92vh` was computed against whatever the browser reports as "100% of the viewport," which in embedded/iframe contexts (like an artifact preview pane) or with mobile browser chrome can legitimately be taller than what's actually visible on screen — so a panel sized at 92% of that reported height can still end up with its bottom edge below the fold. **Fix:** the sheet panel now uses a `.shred-sheet-panel` CSS class (in the injected `<style>` block) with a more conservative `82vh` base, an `@supports (height: 100dvh)` progressive enhancement to `85dvh` (dynamic viewport height — the modern, purpose-built unit that tracks the *actually visible* area and updates as browser chrome shows/hides), and a `@media (min-width: 768px)` cap of `620px` so the sheet doesn't needlessly stretch tall on desktop where there's no mobile-chrome ambiguity to begin with. ## Known Simplifications / Intentional Choices
- Macro colors (kcal/protein/carbs/fat) and goal colors are intentionally **not** bound to the user's accent choice — see the Sprint 7 design-decision note above.
- Day-mode colors (training=cyan, rest=violet) and Power/Volume workout-day colors (cyan/violet) also stay fixed across accent changes, so switching accent never removes the training-vs-rest or power-vs-volume visual distinction.
- Mifflin-St Jeor is applied without a sex/gender term (per the Sprint 6 spec's exact formula, which uses a flat `+5`).
- Timeline slots 08:00/10:30/16:30 are fixed sample meals (breakfast, mid-morning snack, pre-workout shake) — not yet swappable like lunch/dinner. Candidate for a future sprint.
- Only one rest timer can run at a time (matches real training — you rest one exercise at a time).
- Custom profiles are seeded with generic template values (28y/75kg/175cm/90cm, office activity, maintenance goal) rather than blank fields, so the calculator never divides by zero or shows `NaN`.
- Sound feedback needs a user gesture to unlock Web Audio (browser policy) — the very tap that triggers feedback also satisfies this, so no separate "enable audio" step is needed.
- The onboarding tour highlights whole Arena groups (header / macro+timeline / cibus+hacks / workout+metrics) rather than individual sub-widgets, keeping the spotlight logic simple (4 refs) while still walking through every major zone of the dashboard.
- The AI Coach's "analysis" is rule-based, not a real language model — see the Sprint 9 note above for why that's the honest and correct choice here, not a corner cut.
- `parseFoodText` matches the *first* occurrence of each food's keyword only (via a `seenLabels` set), so a sentence mentioning the same food twice will only log it once — a reasonable tradeoff for a lightweight heuristic parser over building a full tokenizer.
- The API key field never triggers a real network call in this build; it's an honestly-labeled placeholder for a future live-chat integration, not a partially-working feature.
- The heatmap's history (beyond today) is seeded synthetic data, not a real multi-day log the app has been quietly building — there was no prior mechanism to record past days, so this is the honest way to make the analytics view non-empty on a fresh session while today's cell stays fully live/real.
- Heatmap columns are sequential 7-day chunks, not calendar-aligned Sunday-start weeks (see the Sprint 10 note above).
- The weekly report's "workout days" count and compliance average are both drawn from `dailyLogs`, which only has one entry per calendar date — logging two workouts in one day isn't distinguished from one.
- The four original Cibus restaurants (Shumshum, Chicken Station, Goomba, Kansai) are not editable — only newly-created custom restaurants get the editable 3-part-formula/dish-list power. See the Sprint 11 scope-decision note above for why.
- `buildFoodLibrary()` recomputes the full combinatorial candidate list (including every Shumshum/Chicken-Station/Kansai combination) on every render rather than memoizing it — fine at this data size (well under 100 candidates), but would want `useMemo` if the custom restaurant/hack lists grew very large.
- Deleting a custom restaurant or hack does not retroactively change any meal already logged from it (e.g. today's confirmed lunch or a quick-logged Smart Swap) — those keep their already-computed macros, only future selections are affected.
- The in-app Docs Viewer's content (`DOCS_CHANGELOG` etc.) is a hand-maintained condensed copy of this file, not a live parse of `CLAUDE.md` — the two need to be kept in sync manually when either changes.
- `MarkdownLite` supports a deliberately small subset (`##`, `-`, `` ` ``, `**`) — enough for this file's own content, not a general-purpose markdown renderer.
- "איפוס מלא להגדרות יצרן" resets in-memory state and deletes the `window.storage` entry; it cannot un-download any JSON backups the person already exported (which is correct — backups are meant to survive a reset).
- The completion certificate's stats are only as complete as `dailyLogs`/`metricEntries` — on a brand-new session before any real interaction, most of what it shows still reflects the Sprint 10 synthetic seed history, same caveat as the heatmap.
- `INGREDIENT_DB`'s cooked-factor numbers are reasonable nutrition-science approximations (chicken/beef/salmon ~0.75-0.85, rice/pasta/couscous ~2.2-2.6), not laboratory-measured constants — real yield varies by cooking method (grilled vs. boiled vs. baked) and cut.
- The "תקציב נותר להיום" strip in the Plate Composer shows the whole day's remaining budget, not a per-slot target — it's a sizing reference, not a hard constraint the composer enforces.
- Custom ingredients are always treated as single-state (no raw/cooked toggle) since a packaged product's nutrition label already reflects its normal weighed state.
- The Plate Composer's ingredient list has no search/filter beyond the 4 category tabs — fine at ~30 built-in ingredients, would want a search box if the custom ingredient list grows very large.
- `QuickLogSheetBody` (FAB → "רישום חופשי") and the quick-log section inside `AiCoachWidget` (Insights tab) are two separate components sharing the same underlying `parseFoodText`/`logItems` logic, not one shared component — a small deliberate duplication so the FAB's quick action doesn't require navigating to Insights first, kept intentionally simple rather than over-engineering a shared abstraction for two call sites.
- The onboarding tour is back to 4 steps mapped onto Today/Nutrition/Workouts (plus the header) and no longer has a dedicated Insights step, matching the original Sprint 8 spec's step count — Insights is still fully reachable via the bottom nav, just not part of the guided tour.
- `getCurrentSlotId()`'s "current slot" logic is a simple time-window heuristic (next slot without a completed item within 90 minutes of now, else next upcoming, else the last slot) — it doesn't account for the person's actual eating pace or timezone edge cases.
- `grams` on a logged item is a **portion index** (100 = the amount as originally logged), not a literal weight, for anything other than a raw ingredient — see the Sprint 15 note above. Editing "grams" to 150 means "1.5× whatever I originally logged," which scales correctly for a Cibus plate or a quick-log snack even though neither has a true per-gram rate.
- The heatmap/weekly-report/certificate stats blend real logged data (`itemsByDate`) with Sprint 10's synthetic seed data for any date that's never been touched — a date the person has interacted with even once is thereafter always real, never synthetic, but a completely untouched historical date stays synthetic indefinitely (there's no mechanism to "expire" old seed data other than the person logging something for that date).
- Multiple items can now share a slot (e.g. two snacks both logged to "ביניים") — this is a deliberate improvement over the old one-meal-per-slot model, but means a slot's "done" state in `SmartContextCard` requires *all* its items to be completed, not just one.

### Sprint 16.1 — Mobile Bugfix: the On-Screen Keyboard Hides Sheet Content
Reported with mobile screenshots: while typing in the Plate Composer's search box on a phone, the on-screen keyboard covered the bottom of the sheet (the portion input and "הוסף לצלחת" button), and the person had to fight the keyboard to reach them.
- **Root cause:** `useViewportHeight()` (the hook powering `SheetModal`'s real, JS-measured height — see Sprint 15.15) read `window.innerHeight`, which on iOS Safari and many mobile browsers does **not** reliably update when the on-screen keyboard opens — the browser's outer window technically stays the same size; only the *visible* area above the keyboard shrinks. So the sheet kept sizing itself for the full screen even though a third of it was now covered by the keyboard.
- **Fix:** the hook now prefers `window.visualViewport.height` when available — the API specifically designed to track the actually-visible viewport, correctly shrinking when the keyboard appears — falling back to `window.innerHeight` on older browsers that lack it. It also listens to `visualViewport`'s own `resize`/`scroll` events, which fire reliably on keyboard show/hide where `window`'s `resize` event often doesn't.
- **Also added:** tapping a search result in the Plate Composer or Eating Out list now calls `document.activeElement.blur()`, dismissing the keyboard automatically the moment a choice is made — so the person doesn't have to manually close the keyboard to see the portion input and add button that follow.

### Sprint 16.2 — Critical Bugfix: Data Loss on the Same Device, Not Just Cross-Device
Reported directly: logging a full day of meals, then exiting and re-opening the Claude app on the *same* phone, showed everything wiped — not a sync issue, a real data-loss bug.
- **Root cause:** every save to `window.storage` was debounced by 350ms (`setTimeout`) to avoid writing on every keystroke. If the person left the app (backgrounded it, closed the tab, switched apps) *before* that 350ms timer fired, the pending save was simply lost — mobile browsers and app webviews routinely throttle or tear down JS timers the moment a page loses focus or visibility, and "log a meal, immediately switch apps" is an extremely normal, fast mobile interaction pattern. This wasn't a storage-API limitation; it was this app's own save timing not accounting for how quickly people actually leave.
- **Fix:** a `latestStateRef` now always mirrors the current save-relevant state (avoiding stale-closure bugs in a listener registered once on mount). A second effect registers `visibilitychange`, `pagehide`, and `blur` listeners that immediately flush an **un-debounced** save to `window.storage` the instant the app is backgrounded or about to unload — a standard, well-established pattern for exactly this class of "save before the user leaves" problem. The original 350ms debounced save is kept as-is for the normal case (reduces write frequency during active typing/logging); the new listeners are the safety net that guarantees nothing is lost when someone exits abruptly, which is the common case on mobile.
- The load-on-mount effect was re-checked as part of diagnosing this and confirmed correct (runs once, `[]` dependency array, no re-trigger risk) — the bug was entirely on the save side, not a reset-on-load issue.

## Sprint 17 — Infrastructure Migration: artifact → Next.js + Supabase (in progress)

The app outgrew its host. `window.storage` only works for a published artifact, is scoped in
ways that don't reliably survive across devices, and has no concept of a user account — none
of which is fixable from inside a single file. This sprint moves the same product onto
Next.js (App Router) + Supabase (Postgres, Auth, RLS) with Google sign-in, without changing
any product logic. The artifact is preserved verbatim at `reference/ProjectShred.artifact.jsx`
as the source of truth for the port; full plan and rationale in `docs/MIGRATION.md`.

**Milestone 1 (done): schema, RLS and views.** Ten user-owned tables replacing the single
JSON blob, all with RLS on before any client code existed. Notable calls:

- **`grams` stays a portion index in the database too**, and the `base × grams/100` scaling is
  deliberately *not* a generated column or a view — it runs on every render, so it stays a
  pure client function. The only place SQL does the arithmetic is the `daily_totals`
  aggregate.
- **`daily_totals` filters on `is_completed`.** The obvious `SUM(...) GROUP BY date_key` would
  have silently folded in unticked items — `sumItems()` skips them — inflating every heatmap
  score and weekly-report average. It also rounds *per item* before summing, because
  `scaleLoggedItem()` does, and summing-then-rounding drifts from what the hero ring shows for
  the same day. Both are pinned by tests.
- **`dailyLogs` was split rather than dropped.** Totals are derived, but `workoutDone`/
  `workoutDay` are stored nowhere else and aren't derivable from food logs, and `DayEditor`
  writes kcal/protein into dates that have no items behind them. Those live in `day_meta`; the
  `daily_log` view full-outer-joins the two so a workout logged on a day with no food still
  produces a row.
- **The Sprint 10 synthetic seed history is not ported.** Real accounts have real history from
  day one, and the seed-vs-real ambiguity was already a known wart (see Known Simplifications).
  New accounts start with an empty heatmap.
- **`apiConfig.key` is dropped entirely.** Sprint 9 established it never fired a request.
  Carrying an inert secret field into an app with real accounts creates a credential surface
  for a feature that does nothing; only `ai_provider` survives.
- **Reference data (`INGREDIENT_DB` 279 / `HACKS` 64 / `EATING_OUT_MENU` 73, the Cibus
  builders, `WORKOUTS`) stays in version-controlled TypeScript, not Postgres.** It's static,
  never user-written, read on every keystroke of the Plate Composer search, and feeds
  `buildFoodLibrary()`'s per-render enumeration. A table would add latency to the hottest path
  and cost the literal types.
- **`dateKey()`'s local-time discipline is now a schema rule.** Postgres `now()::date` and
  `current_date` are UTC on Supabase, and Israel is UTC+2/+3 — the exact shape of the Sprint
  15.2 bug, one layer down. No table defaults a date; every `date_key` is computed client-side
  from local calendar components and sent explicitly.
- **RLS details worth keeping:** policies use `(select auth.uid())` so the planner hoists it to
  an InitPlan instead of re-invoking per row; `user_id` defaults to `auth.uid()` so a client
  insert that omits it can't write NULL and fail with a confusing error; and both views are
  `security_invoker = true` — without that a view runs as its owner (a superuser on Supabase)
  and bypasses RLS entirely, which is a silent, total data leak.

`supabase/tests/` stands up a minimal local shim of Supabase's `auth` schema so the migrations
can be applied and exercised against plain Postgres in CI. 27 assertions cover the bootstrap
trigger, totals parity with `sumItems()`, the override rules, the constraints protecting
domain logic, real cross-user isolation from inside the `authenticated` role, and cascade on
account deletion.

**Remaining:** domain-logic extraction with tests pinned to the artifact's current outputs
(next, and deliberately before any component moves), reference-data porting, auth, the
sync store, the UI port, and JSON-backup import so existing artifact data can be brought in.

**אימות אמיתי בדפדפן, לא רק בדיקות יחידה:** הורצה שרת פיתוח אמיתי וצולמו מסכים עם Playwright — כולל תרחיש גרירה מלאה (אצבע יורדת, האמצע גרירה, שחרור) שהוכיח בוויזואלית שהגרירה-לסגירה עובדת בפועל, לא רק שהקוד מתקמפל. 148 בדיקות (24 קבצים) עוברות, `typecheck`/`lint`/`build` נקיים.

## סיכום ספרינט 5 — מעבר עומק ויזואלי (Glassmorphism מבוקר)

**הקשר וכיוון עיצובי:** התבקשתי לבצע שדרוג עומק/פרימיום אגרסיבי — זכוכית עבה בכל מקום, זוהר ניאון, ניווט תחתון "אי צף" מנותק מהמסך. הערתי מראש (ב-`AskUserQuestion`, ללא מענה) שהמנדט הזה בעצם הופך החלטה מתועדת של ספרינט 7: המעבר המכוון מ"זכוכית שקופה כברירת מחדל" למשטחים אטומים ("matte")+זוהר מרוסן, בעקבות פידבק ישיר שהתיאור הקודם נראה "AI גנרי". כשלא התקבל מענה להערה, המשכתי לפי שיקול דעת: **עומק אמיתי, אך מרוסן** — לא מחיקה של הגיון ספרינט 7, אלא איטרציה נוספת מעליו. שינוי כיוון קיצוני (`bg-white/[0.02]` שקוף-כמעט-לגמרי, או מעבר לפלטת Tailwind גנרית) נפסל במפורש כי הוא היה חוזר בדיוק לבעיה שספרינט 7 כבר פתר.

**`GlassCard.tsx` — שוכתב:** רקע הקסדצימלי-שקוף (`${T.t.card}B8` בכהה / `${T.t.card}F0` בהיר — נשאר בתוך מערכת ה-Tokens הקיימת, לא צבע חדש), `backdropFilter: blur(20px) saturate(160%)` כך שתוכן מאחורי הכרטיס באמת נראה דרכו, הדגשה פנימית עדינה (`inset box-shadow` לבן שקוף) ליצירת תחושת עומק אמיתית, וצל כפול-שכבה (צל הבסיס הקיים של הטמה + שכבת "הילה" רחבה יותר בצבע האקסנט כשמוגדר `accent`).

**`BottomNav.tsx` — הניווט נותק מקצה המסך:** במקום פס מלא-רוחב צמוד לתחתית, זו כעת "כדור זכוכית" צף (`rounded-full`, שוליים 20px, `bottom: calc(env(safe-area-inset-bottom) + 16px)`) עם `backdrop-blur(24px) saturate(160%)` וצל אמבינטי תלת-שכבתי. אינדיקטור הטאב הפעיל (`layoutId`, קפיץ מספרינט 3) קיבל גם זוהר עדין בצבע האקסנט.

**`ActionFab.tsx` — מרקע שטוח לגרדיאנט תלת-מימדי:** `background: T.accent` שטוח הוחלף בגרדיאנט `color-mix()` (בהיר→אקסנט→כהה, אותו גוון בדיוק, בלי צבע חדש) פלוס זוהר כפול-שכבה. **תופעת לוואי אמיתית שטופלה מיד:** מיקום ה-FAB (`bottom`) השתנה כדי לפנות מקום מעל הניווט הצף החדש — בדיוק סוג הבאג שתועד בספרינט 15.7 (רכיב נייח שמכסה כפתור אחר). כדי למנוע הישנות: `FAB_BOTTOM`/`FAB_SIZE` יוצאו כקבועים מיוצאים מהקובץ, ו-`FabMenu.tsx` מחשב את מיקומו (`MENU_BOTTOM`) *מהם* ישירות במקום מספר קסם נפרד — כך שאם מיקום ה-FAB ישתנה שוב בעתיד, התפריט לא יכול לצאת מסונכרן.

**`CompositeHeroRing.tsx` — זוהר ניאון על הטבעת:** כל קשת (קלוריות/חלבון) מקבלת `<filter>` של SVG משלה (`feGaussianBlur`+`feMerge` — הטכניקה התקנית לזוהר-על-קו, כי `filter: drop-shadow` פשוט מטשטש את כל האלמנט כולל הקצה החד). מזהי ה-filter מיוצרים דרך `useId()` כדי שלא יתנגשו אם הרכיב אי-פעם ירונדר פעמיים. **נבדק במפורש:** שום מקום לא משתמש ב-`font-black` על טקסט עברי — הגופן `IBM Plex Sans Hebrew` הטעון כולל רק משקלים 400–700 (ראו הערת ספרינט 15.14), ו-`font-bold` (700) שכבר בשימוש כאן בטוח.

**`globals.css` — שתי תוספות סטטיות:** `::-webkit-scrollbar-thumb` (אפור שקוף, ניטרלי לשני המצבים) ו-`::selection` (גוון Jade סטטי). **הערה כנה:** צבע `::selection` תלוי-אקסנט אמיתי דורש גישת `useTheme()` בזמן ריצה — כלומר רכיב הזרקת-סטייל שעדיין לא קיים בפרויקט. במקום לבנות תשתית שלמה לכלל CSS אחד, נבחר ברירת מחדל סטטית בגוון המותג; תועד כאן כפריט לספרינט עתידי אם באמת נדרש שיהיה תלוי-אקסנט חי.

**`app/page.tsx` — שכבת רקע אמביינטית:** שני "בלובים" גדולים, מטושטשים מאוד (`blur(60-70px)`), בגווני האקסנט וצבע החלבון, ב-`position: fixed` (לא `absolute`) כדי שיתפקדו כאטמוספירה של הדף ולא יגללו עם התוכן — `pointer-events-none` ו-`z-index` שלילי כדי שלעולם לא יפריעו למגע. `paddingBottom` הותאם מ-132 ל-190 כדי לפנות מקום אמיתי לניווט הצף + ה-FAB שמעליו (שניהם גבוהים יותר מהפס הישן הצמוד לקצה).

**באג אמיתי שנתפס ותוקן תוך כדי הבדיקה בדפדפן, לא רק בבדיקות יחידה:** בזמן הרצת שרת פיתוח + Playwright, קונסולת הדפדפן הראתה אזהרת React אמיתית: `Cannot update a component (Home) while rendering a different component (WorkoutPanel)`. הסיבה: `toggleSet` קרא ל-`onWorkoutActivity` (שמזרים ל-`store.setWorkoutActivity`, סטור אחר) **מתוך** ה-updater הפונקציונלי של `setLog` — קריאה כזו יכולה לרוץ ע"י React בזמן רינדור, מה שהופך קריאת `setState` לרכיב אחר לבעייתית. התיקון: חישוב ה-state החדש ישירות מה-closure הנוכחי וקריאה ל-`setLog`/`onWorkoutActivity` ישירות בגוף ה-event handler, לא בתוך ה-updater. **נוסף גם מבחן רגרסיה ייעודי** (`WorkoutPanel.test.tsx`) שמרגל אחרי `console.error` ומוודא שהאזהרה הזו לעולם לא תחזור.

**באג לינט נוסף שנפתר בדרך "נכונה" ולא בעקיפה:** שני `useEffect` (סנכרון שדות המשקל/חזרות ב-`ExerciseRow`, וספירת הטיימר לאחור ב-`WorkoutPanel`) הפעילו את כלל ה-lint `react-hooks/set-state-in-effect`. הראשון נפתר לפי הדפוס הרשמי של React ("איפוס state כשprop משתנה" → מפתח `key` שגורם ל-remount, לא effect) — `WorkoutPanel` מזהה כל שורה כעת ב-`` `${selectedDateKey}-${ex.name}` ``, כך שמעבר תאריך מאתחל את הרכיב מחדש עם הערך הנכון בלי לכתוב עליו. השני נפתר ע"י הזזת מעבר ה-state ל-0 מתוך גוף ה-effect הסינכרוני אל תוך ה-callback של ה-`setTimeout` עצמו.

**"מחובר במלואו למנגנון הסנכרון המבוסס-Debounce שלנו" — מענה כן, לא מזויף:** בדקתי ומצאתי ש-`createSyncScheduler` (מנגנון ה-Debounce+Flush של ספרינט 16.2, שחולץ במילסטון 2) **מעולם לא היה מחובר בפועל** לחנות — לא רק עבור אימונים, עבור *שום* דבר באפליקציה. זו לא בעיה שנוצרה השבוע, זו פינה פתוחה שתועדה בכנות בסיכום מילסטון 2 ("ה-Persist בפועל... עדיין לא קיים"). עכשיו זה באמת מחובר:

- **הערה כנה על הגבול האמיתי:** `lib/store/persist.ts` — הפונקציה שבאמת כותבת ל-Supabase — היא עדיין stub מתועד. אין עדיין לקוח Supabase מאומת בשום מקום באפליקציה (Milestone 5 / Auth טרם בוצע), וכל הטבלאות מוגנות ב-RLS לפי `auth.uid()` — כתיבה אנונימית פשוט תידחה. מה שכן אמיתי: כל מנגנון התזמון (Debounce, Flush בעת יציאה) **רץ בפועל** נגד ה-stub הזה עכשיו; כשה-Auth יגיע, צריך למלא רק את הגוף של `persistShredState()`, לא לבנות את החיווט מסביבו.
- **החלטת ארכיטקטורה קטנה אך משמעותית:** סטטוס הסנכרון (`saving`/`saved`/`error`) נשמר בסטור Zustand **נפרד** (`useSyncStatusStore`), לא כשדה בתוך `ShredState` הראשי. הסיבה: אילו ה-callbacks של ה-scheduler (`onSaving`/`onSaved`) היו כותבים חזרה לתוך `shred-store` עצמו, זו הייתה יוצרת לולאה אינסופית — כל עדכון סטטוס היה משנה את החנות, מה שהיה מפעיל שוב את אותו ה-subscribe שקרא ל-`notify()`, שמתזמן עוד Flush, לנצח. הפרדת הסטורים פותרת את זה מיסודו.
